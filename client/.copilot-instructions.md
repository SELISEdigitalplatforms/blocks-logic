# Blocks IDP Client - Copilot Context

## Project Overview
This is an extracted IDP (Identity Provider) client application built with **Vite + React 18.3.1** with **React Router v6.28.0**. It's a component of the larger Blocks platform, extracted from the monolith for independent development.

## Architecture & Stack
- **Framework**: Vite + React 18.3.1 (not Next.js - uses React Router instead)
- **UI Library**: Radix UI (@radix-ui/*) with shadcn/ui patterns
- **State Management**: Zustand (v5.0.1) with persist middleware for localStorage
- **Data Layer**: TanStack React Query v5.62.11 for API caching
- **HTTP Client**: Custom HttpClient at `/app/lib/http-client.ts` with JWT token rotation, Blocks-Key header support
- **CSS Framework**: Tailwind CSS v3.4.1 with custom color tokens
- **Typography**: DM Sans from Google Fonts (required - added to match monolith)
- **Icons**: lucide-react (v0.445.0)
- **Theming**: CSS variable-based (light/dark modes via `dark` class on root)

## Key Features Implemented
1. **Monolith Shell Port**: Complete navigation shell ported from blocks-app-next monolith
   - Collapsible desktop sidebar (min-w-60 open, w-14 closed)
   - Theme-aware logo transitions (Logo.svg / Icon.svg based on theme and sidebar state)
   - Mobile sheet drawer navigation
   - Top navbar (DashboardHeader) with project/environment selectors

2. **Menu Structure**: IDP-scoped menu with 4 subitems
   - Authentication
   - Access Manager
   - MFA
   - Captcha

3. **Layout Architecture**:
   - **AdminLayout**: For service routes (`/services/*`) - includes sidebar, dashboard header, full shell
   - **ConsoleLayout**: For profile page (`/profile`) - no sidebar, minimal header with "Back to Console" button
   - **ProtectedGuard**: Protects all routes requiring authentication

4. **State Management**:
   - `useAuthStore`: Authentication, tokens, user info (from `/app/store/auth.store.ts`)
   - `useProjectStore`: Project/environment selection, persistent across navigation (from `/app/store/project.store.ts`)
   - `useLanguageViewStore`: Language selection
   - `SidebarContext`: React Context for sidebar open/close state, localStorage persistence

5. **UI Components**:
   - Sidebar with desktop/mobile variants
   - Project & Environment dropdowns with live API data
   - User dropdown menu with profile link and logout
   - Theme toggle (light/dark)
   - Notification placeholder (bell icon)
   - Back-to-console navigator button on profile page

## Important Styling Details (Matched to Monolith)
- **Background Colors**: Both sidebar and header use `bg-background` CSS class
  - Light mode: White (#FFFFFF)
  - Dark mode: Dark navy (#0a0e27)
- **Header Spacing**: Responsive margins `mx-5 sm:ml-1 sm:mr-6` (mobile 1.25rem, desktop 1rem/1.5rem)
- **Font**: DM Sans applied via `--font-sans` CSS variable in globals.css
- **Component Heights**: 
  - Header: `h-[60px]` (60px)
  - Sidebar: `h-[calc(100vh)]`, width varies on collapse

## Key Files & Their Purpose
- **admin-layout.tsx**: Main app layout wrapper, combines sidebar + dashboard header
- **router.tsx**: Route configuration with separate layouts for AdminLayout and ConsoleLayout
- **dashboard-layout-provider.tsx**: Sidebar state management via React Context
- **project.service.ts**: Calls `/identifier/v1/Project/Gets` and `/identifier/v1/Project/Get` endpoints
- **navigation-menus.tsx**: Menu structure (Identity menu with 4 subitems)
- **use-project.ts**: `useGetProjects()` hook fetches and syncs to Zustand store

## Routing Structure
```
/login                           -> LoginPage
/services/authentication         -> AdminLayout (with sidebar) + AuthenticationPage
/services/access                 -> AdminLayout (with sidebar) + AccessPage
/services/iam                     -> AdminLayout (with sidebar) + IAMPage
/services/mfa                     -> AdminLayout (with sidebar) + MFAPage
/services/captcha                 -> AdminLayout (with sidebar) + CaptchaPage
/profile                          -> ConsoleLayout (no sidebar, back button) + ProfilePage
/forgot-password                  -> Standalone (no layout)
```

## State Flow
1. User logs in → stores JWT in `useAuthStore`, redirects to `/services/authentication`
2. `AdminLayout` loads → `SidebarContext` initializes with localStorage sidebar state
3. `useGetProjects()` fetches projects from API → syncs to `useProjectStore`
4. Project/environment selection persists in store across navigation
5. Logout: resets auth store → clears project store → clears React Query cache → redirects to `/login`

## Common Tasks
- **Adding a new menu item**: Edit `/app/constants/navigation-menus.tsx`, add to `navigationMenus` array
- **Changing theme colors**: Edit `/app/styles/globals.css` CSS variables (--background, --foreground, etc.)
- **Adding a new page**: Create component in `/app/idp/*/pages/`, add route to `/app/router.tsx`, add menu item if needed
- **Debugging sidebar state**: Check `SidebarContext` in `dashboard-layout-provider.tsx`, use React DevTools Context inspector
- **Checking project sync**: Use `useGetProjects()` hook, verify data flows to `useProjectStore`
